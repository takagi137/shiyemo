# BDD 场景写法指南

> BDD（Behavior-Driven Development）：用 Given-When-Then 结构描述系统行为，作为人与 AI 的"行为契约"。
> 本文档定义"失业么"项目中 BDD 场景的写法规范。

---

## 什么是 BDD

```
Given: 系统处于某个初始状态
When:  用户执行某个操作
Then:  系统应产生某个结果
```

BDD 场景有两个消费者：
1. **人**：审阅场景，确认系统行为符合预期
2. **AI**：基于场景编写代码，并验证代码是否通过

---

## 本项目的 BDD 格式

不使用 Gherkin（.feature），使用 **Markdown 格式的 .feature.md** 文件：
- 更适合 AI 理解和生成
- 不需要 cucumber 工具链
- 可以包含中文说明和表格
- 便于在 Git 中 review

## 场景文件模板

```markdown
# spec：<场景标题>

> 所属模块：xxx
> 优先级：P0/P1/P2
> 创建时间：2024-xx-xx

## 场景描述

简要描述这个场景代表什么业务含义、用户会遇到什么情况。

## 规格

### Given <前置条件>

描述系统和数据的初始状态：

- 用户状态：未登录 / 已登录（用户ID=x）
- 数据库状态：存在/不存在某些数据
- 系统状态：缓存、配置等

### When <操作>

描述用户或系统执行的动作：

- API 调用：方法 + 路径 + 请求体
- 用户操作：点击、输入、滑动等
- 定时任务触发、事件触发等

### Then <预期结果>

描述系统应该产生的结果：

- 响应状态码
- 响应体内容
- 数据库变更
- 其他副作用（通知、缓存更新等）

## 验证方式

| 验证项 | 方式 | 预期值 |
|--------|------|--------|
| 响应状态码 | HTTP | 200 |
| 数据库记录 | SQL 查询 | 新增 1 条 |
| 响应时间 | 压测 | < 200ms |
```

---

## 场景分类

### P0：必须覆盖的核心场景

| 场景类型 | 说明 | 示例 |
|---------|------|------|
| 成功路径 | 用户顺利完成操作 | 注册成功、发帖成功 |
| 关键异常 | 影响用户体验的错误 | 登录失败、权限不足 |
| 数据完整性 | 确保数据一致 | 创建后查询、事务回滚 |

### P1：应该覆盖的边界场景

| 场景类型 | 说明 | 示例 |
|---------|------|------|
| 边界值 | 最大/最小/空值 | 昵称 0 字符、昵称 50 字符 |
| 并发 | 多人同时操作 | 同一帖子同时被点赞 |
| 重复操作 | 同一操作多次执行 | 重复点赞应为取消 |

### P2：可以覆盖的增强场景

| 场景类型 | 说明 | 示例 |
|---------|------|------|
| 性能 | 响应时间、吞吐量 | 列表页 100ms 内返回 |
| 安全 | SQL 注入、XSS | 输入特殊字符不报错 |
| 降级 | 依赖服务不可用 | 短信服务不可用时的处理 |

## 场景示例

### 示例 1：用户注册 - 成功场景 (P0)

```markdown
# spec：用户注册 - 成功场景

> 所属模块：认证 (auth)
> 优先级：P0

## 场景描述

新用户使用手机号 + 验证码成功注册账户，注册后自动登录并跳转首页。

## 规格

### Given 用户满足注册条件
- 用户未登录（无有效 token）
- 手机号 13800138000 未被注册
- 验证码 123456 已发送到该手机号，且在有效期内

### When 用户提交注册请求
- 请求：POST /api/v1/auth/register
- 请求体：
  ```json
  {
    "phone": "13800138000",
    "code": "123456",
    "nickname": "测试用户",
    "password": "a123456"
  }
  ```

### Then 注册成功
- 响应状态码：200
- 响应体：
  ```json
  {
    "code": 0,
    "message": "ok",
    "data": {
      "token": "<JWT token>",
      "user": {
        "id": "<uuid>",
        "phone": "13800138000",
        "nickname": "测试用户"
      }
    }
  }
  ```
- 数据库验证：
  - `users` 表新增 1 条记录
  - `phone` = "13800138000"
  - `nickname` = "测试用户"
  - `password_hash` 不等于明文 "a123456"
```

### 示例 2：发帖 - 参数校验 (P1)

```markdown
# spec：发帖 - 标题过长

> 所属模块：帖子 (post)
> 优先级：P1

## 场景描述

用户发帖时标题超过 200 字符限制，系统应拒绝并返回明确错误信息。

## 规格

### Given 用户已登录
- 用户已登录，token 有效
- 用户 ID = "user-123"

### When 用户提交超出长度限制的标题
- 请求：POST /api/v1/posts
- 请求体：
  ```json
  {
    "type": "emotion",
    "title": "<201 个字符的标题>",
    "content": "正常的内容"
  }
  ```

### Then 发帖失败
- 响应状态码：400
- 响应体：
  ```json
  {
    "code": 40002,
    "message": "标题长度不能超过 200 字符"
  }
  ```
- 数据库验证：
  - `posts` 表无新增记录
```

### 示例 3：点赞 - 幂等性 (P1)

```markdown
# spec：点赞 - 重复点赞取消

> 所属模块：互动 (interaction)
> 优先级：P1

## 场景描述

用户对已点赞的帖子再次点赞，系统应视为取消点赞。

## 规格

### Given 用户已点赞该帖子
- 用户已登录，user_id = "user-123"
- 帖子 post_id = "post-456"
- users_likes 表存在记录：{user_id: "user-123", post_id: "post-456"}
- posts 表 like_count = 10

### When 用户再次点赞该帖子
- 请求：POST /api/v1/posts/post-456/like
- 请求头：Authorization: Bearer <token>

### Then 取消点赞成功
- 响应状态码：200
- 响应体：`{ "liked": false, "like_count": 9 }`
- 数据库验证：
  - `users_likes` 表记录被删除
  - `posts` 表 `like_count` 变为 9
```

### 示例 4：Feed 流 - 默认排序 (P0)

```markdown
# spec：Feed 流 - 默认按最新排序

> 所属模块：Feed 流 (feed)
> 优先级：P0

## 场景描述

用户打开首页，看到帖子按创建时间倒序排列。

## 规格

### Given 数据库中存在多篇帖子
- 数据库中有 3 篇帖子：
  - post_1：created_at = "2024-01-03 10:00"
  - post_2：created_at = "2024-01-02 10:00"
  - post_3：created_at = "2024-01-01 10:00"

### When 用户请求首页 Feed
- 请求：GET /api/v1/feed?sort=latest&page=1&size=20

### Then 返回按时间倒序的帖子列表
- 响应状态码：200
- 响应体：
  ```json
  {
    "code": 0,
    "data": {
      "list": ["post_1", "post_2", "post_3"],  // 按 created_at 倒序
      "page": 1,
      "size": 20,
      "has_more": false
    }
  }
  ```
```

## 场景覆盖检查清单

完成一个模块的开发前，检查以下场景是否都有对应的 spec 文件：

### 用户系统 (auth)

- [ ] 注册 - 成功
- [ ] 注册 - 手机号已存在
- [ ] 注册 - 验证码错误
- [ ] 注册 - 昵称重复（允许还是不允许？需要确认）
- [ ] 注册 - 密码太短
- [ ] 登录 - 成功
- [ ] 登录 - 手机号不存在
- [ ] 登录 - 密码错误
- [ ] 登录 - 账号被封禁

### 帖子系统 (post)

- [ ] 发帖 - 成功
- [ ] 发帖 - 标题为空
- [ ] 发帖 - 标题过长
- [ ] 发帖 - 内容为空
- [ ] 编辑帖子 - 成功
- [ ] 编辑帖子 - 非作者编辑
- [ ] 删除帖子 - 成功
- [ ] 删除帖子 - 非作者删除
- [ ] 获取帖子详情 - 成功
- [ ] 获取帖子详情 - 帖子不存在

### Feed 流 (feed)

- [ ] 默认排序 - 最新优先
- [ ] 排序切换 - 最热优先
- [ ] 分页 - 第一页
- [ ] 分页 - 最后一页
- [ ] 分页 - 超出范围
- [ ] 类型筛选 - 只看 emotion
- [ ] 空数据 - 无帖子时

### 互动系统 (interaction)

- [ ] 点赞 - 成功
- [ ] 点赞 - 已点赞（取消）
- [ ] 收藏 - 成功
- [ ] 收藏 - 已收藏（取消）
- [ ] 评论 - 成功
- [ ] 回复评论 - 成功
- [ ] 删除评论 - 成功

## AI 生成场景的指令模板

让 AI 为某个模块生成场景时，使用以下指令：

```markdown
请为 `docs/05-场景验证/01-post.feature.md` 生成发帖模块的 BDD 场景文件。

要求：
1. 按本文档定义的格式输出
2. 优先生成 P0 场景，再生成 P1
3. 每个场景一个独立文件
4. 包含 Given/When/Then 和验证方式
5. 响应格式遵循 `docs/01-架构/03-api-design.md` 定义的统一格式

发帖模块功能：
- 创建帖子（支持 type: emotion/insight/case/action）
- 编辑帖子（仅作者可编辑）
- 删除帖子（软删除）
- 获取帖子详情
```
