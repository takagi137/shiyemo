## 执行计划

### 执行顺序

```
Phase 1 (P0): search → tag → report
Phase 2 (P1): admin → auth → follow → interaction → notification
Phase 3 (P2): comment → post → moderation → upload → user → websocket
```

### 每个模块的执行步骤

1. **分析现有测试**：查看当前测试覆盖的函数和逻辑
2. **识别未覆盖逻辑**：找出核心逻辑中未测试的部分
3. **设计测试用例**：基于核心逻辑设计测试场景
4. **实现测试代码**：编写测试代码，使用 mock 或真实数据库
5. **运行验证**：确保测试通过且覆盖率提升
6. **Git 提交**：提交测试代码

### 验证标准

- 每个模块覆盖率 ≥ 50%
- 所有测试通过（`go test -p 1 ./internal/...`）
- 测试真实反映业务逻辑，无虚假测试

## 注意事项

1. **不允许虚假测试**：测试必须真实反映业务逻辑，不能为了覆盖率而写无意义的测试
2. **核心逻辑优先**：优先测试核心业务逻辑，而不是边界情况
3. **Mock 优先**：能用 mock 的模块优先用 mock，减少数据库依赖
4. **真实数据库测试**：需要集成测试的模块使用真实数据库
5. **遵循 OpenSpec**：每个模块的测试规范先写好，再实现测试代码
