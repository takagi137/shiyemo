# proposal：验证标准

## 需求背景

当前项目验证方式过于单一，只有部署后的 curl 验证，缺乏：
- 单元测试（Unit Tests）
- 集成测试（Integration Tests）
- 自动化的 BDD 场景执行

需要建立完整的验证体系，确保代码质量。

## 用户故事

1. 作为开发者，我希望每次提交代码前能自动运行单元测试，确保新代码不破坏已有功能
2. 作为开发者，我希望有集成测试覆盖 API 端点，确保接口行为符合预期
3. 作为开发者，我希望部署后能自动运行 BDD 场景，确保系统整体功能正常
4. 作为项目管理者，我希望有测试覆盖率报告，了解代码质量

## 功能范围

### 本次实现（验证基础设施）

- [ ] 创建测试工具函数库
- [ ] 为 auth 模块补充单元测试
- [ ] 为 post 模块补充单元测试
- [ ] 创建集成测试框架
- [ ] 创建 BDD 验证脚本

### 后续迭代

- [ ] 为其他模块补充单元测试
- [ ] CI/CD 集成
- [ ] 覆盖率报告自动化

## 验收标准

1. 每个 service_test.go 至少 3 个测试用例（happy path, edge case, error case）
2. 测试覆盖率：service 层 ≥ 80%
3. 所有测试通过：`go test ./...`
4. BDD 验证脚本执行通过

## 技术约束

- 使用 Go 标准 testing 包
- 使用 testify 断言库
- 使用真实测试数据库（不 Mock 数据库）
- 测试数据隔离（每个测试后清理）
